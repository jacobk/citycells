**Related:** ADR 014, PRD Section 3.11

## Implementation Checklist

### 1. Add Service Worker and Precache App Shell

- Integrate a Service Worker (e.g. Next.js PWA plugin or Workbox) so the app can load when offline.
- Precache: HTML, JS bundles, CSS, and the SQLite WASM binary (`public/sql-wasm/sql-wasm.wasm`).
- Precache or ensure cache-on-first-visit for `/data/malmo_delomraden.geojson` so sub-area boundaries are available offline (or rely on DB-seeded areas if geometry is served from DB).
- Register the Service Worker from the app (e.g. in root layout or a client component that runs once).

### 2. Cache Map Tiles on Use

- Configure the Service Worker to cache map tile requests (OpenStreetMap or current tile URL) in the Cache API when they are fetched.
- Ensure tile requests can be intercepted (same-origin proxy or SW scope). If tiles are cross-origin, use a strategy that caches the response (e.g. `stale-while-revalidate` or cache-on-response).
- Optionally implement cache size limits or eviction so tile cache does not grow unbounded.

### 3. Offline Detection and UI

- Add offline detection: use `navigator.onLine` and the `online` / `offline` window events.
- Expose this via a React hook (e.g. `useOnlineStatus()`) or context so components can react.
- Add an offline indicator (banner or icon) that is visible when the app is offline. Place it so it does not block core navigation (e.g. top banner or corner icon).

### 4. Graceful Degradation When Offline

- When offline, do not call Strava API (sync, re-fetch, activity export, etc.). Disable or hide sync/re-fetch/re-analyze actions that require network, or show them disabled with tooltip "Requires internet."
- External links (e.g. to Strava activity pages) can remain visible; consider adding a short note (e.g. "Opens when online") or leave as-is if the offline indicator is clear.

### 5. Verify Full Navigation Works Offline

- After implementing the above, verify: app loads, map shows (cached tiles + polygons), sub-area list opens, area details open, progress/stats view works. All data should come from SQLite/IndexedDB and cached assets; no network requests required for these flows.

## Acceptance Criteria

- [ ] With network disabled (DevTools offline or airplane mode), the app loads after having been opened at least once with network (app shell served from Service Worker cache).
- [ ] Map view displays previously viewed tiles and sub-area boundaries when offline.
- [ ] Sub-area list and area details panel open and show correct data from local DB when offline.
- [ ] Progress/stats view shows correct data when offline.
- [ ] An offline indicator is visible when `navigator.onLine` is false.
- [ ] Sync / re-fetch / re-analyze (or equivalent) do not run when offline; they are disabled or hidden with clear messaging.
- [ ] No uncaught network errors or broken UI when using the app offline for read-only navigation.

## Notes

- Do NOT duplicate ADR 014 or PRD 3.11 — implement according to those documents; this ticket only references them.
- Map tile caching may require serving tiles through a same-origin path or configuring the SW to cache cross-origin tile responses per browser/SW rules.
- If using `next-pwa` or similar, follow its docs for precache and runtime cache; align cache strategy with ADR 014 (precache app shell + GeoJSON; cache tiles on use).
